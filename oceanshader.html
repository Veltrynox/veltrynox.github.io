Ocean Shader: Compute Shader Wave Simulation & Tessellation

1. Gerstner Waves via Compute Shader

Instead of calculating Gerstner Wave math inside the Vertex Shader for every single vertex in the ocean mesh, I moved the simulation to a GPU Compute Shader.

The Compute Shader outputs a RenderTexture (Displacement Map) and Normal Map. These textures are set as global shader variables and act as a single source of truth across the engine:

  • The Ocean Surface samples them to displace vertices.
  • The Post-Processing Effect reads them to calculate the waterline.
  • Caustics shaders sample the displacement buffer.
  • The C# Physics System reads the buffer for buoyancy calculations.

By baking to textures, we decouple the simulation cost entirely from geometry resolution. We can scale wave complexity (adding FFT waves or extra Gerstner octaves) without touching ocean mesh geometry logic.

2. Split View & Near-Plane Water Line

Initially, I attempted to render the split-view using geometric two-sided masking. This resulted in code bloat and complex conditional logic to handle near-clip plane artifacts.

Eventually, I switched to using the camera near-plane frustum logic. This keeps the code clean, eliminates artifacts, and achieves a pixel-perfect waterline.

3. Distance-Based Tessellation

To achieve realistic small-scale micro-waves without destroying performance, I implemented distance-based Hull and Domain tessellation shaders. I also added displacement flattening towards the horizon, which stabilizes specular highlights and Z-depth testing while maintaining a shorter computed ocean mesh.
